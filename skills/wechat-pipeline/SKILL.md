# 微信公众号全流程编排器 (wechat-pipeline)

## ⚠️ 强制执行协议 (MUST READ FIRST)

**Pipeline 启动后，Claude 必须连续自动执行，不得在确认点以外的任何地方暂停。**

### 绝对禁止行为（违反即错误）

- ❌ **禁止**在门禁评估后展示结果并等待用户反馈，直接进入下一轮或继续
- ❌ **禁止**在门禁每轮之间停顿，评估→修改→评估必须连续执行
- ❌ **禁止**说"已完成第N轮评估，是否继续？"——直接执行下一轮
- ❌ **禁止**说"评估结果：XX分，要我帮你修改吗？"——不达标立即修改
- ❌ **禁止**完成全文后问"要进行质量门禁吗？"——自动进入
- ❌ **禁止**门禁通过后问"要排版吗？"——等确认点3后自动排版
- ❌ **禁止**3个确认点以外的任何中间询问或停顿
- ❌ **禁止**说"下一步我将..."然后停下——直接执行

### 唯一合法停顿点

| 模式 | 确认点 |
|------|--------|
| 完整流程 | 确认点1（选题）、确认点2（大纲）、确认点3（终稿） |
| --from-draft | 仅确认点3（终稿质量报告） |
| --from-topic | 确认点1（选题）、确认点2（大纲）、确认点3（终稿） |

## 入口模式

| 模式 | 命令 | 说明 |
|------|------|------|
| 完整流程 | `/wechat-pipeline "主题" --type opinion` | 从选题开始 |
| 从选题开始 | `/wechat-pipeline --from-topic` | 先获取热点再选题 |
| 从草稿开始 | `/wechat-pipeline --from-draft article.md` | 跳过写作，直接进门禁 |

## 参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| topic | 无 | 主题/方向/想法 |
| --type | opinion | 文章类型 (opinion/tutorial/listicle/commentary/story) |
| --provider | gemini | AI provider |
| --from-topic | false | 从选题阶段开始 |
| --from-draft | 无 | 从已有草稿进入门禁循环 |
| --theme | simple | 排版主题 |
| --max-rounds | 3 | 门禁最大迭代轮数 |

## 完整流程 (6 阶段)

### 阶段 1: 选题 (wechat-topic)

**触发**: 完整流程 或 `--from-topic`

```bash
cd ~/projects/agents-bc376a3719/🧪\ 小项目与测试/wx-format
node index.js topic --niche "<主题关键词>" --analyze --format structured --output /tmp/pipeline-topic.json
```

读取 `/tmp/pipeline-topic.json`，向用户展示 AI 推荐的 5 个选题。

**🔴 确认点 1: 用户确认选题方向**
- 展示推荐选题列表
- 用户选择一个方向，或提供自己的方向
- 记录确认的选题到 `$PIPELINE_TOPIC`
- **用户回复后立即进入阶段2，不要说"好的，开始写大纲"之类的过渡语，直接输出大纲**

### 阶段 2: 写作 - 大纲 (wechat-writer --outline-only)

```bash
node index.js write "$PIPELINE_TOPIC" --type <type> --provider <provider> \
  --outline-only --title-candidates 5 --no-confirm -o /tmp/pipeline-outline.md
```

**🔴 确认点 2: 用户确认大纲**
- 展示大纲 + 5 个标题候选
- 用户选择标题或提供自己的标题
- 用户可调整大纲结构
- **用户回复后立即进入阶段3，直接开始写全文**

### 阶段 3: 写作 - 全文 (wechat-writer)

```bash
node index.js write "$PIPELINE_TOPIC" --type <type> --provider <provider> \
  --no-confirm -o /tmp/pipeline-draft.md
```

注意：将确认后的大纲和选定标题注入到扩写 prompt 中。
输出保存到 `/tmp/pipeline-draft.md`。

**全文完成后立即自动进入阶段4，不得停顿。**

---

### 阶段 4: 质量门禁循环（完全自动，禁止任何中间停顿）

**入口**: 全文写完后 或 `--from-draft`

> ⚠️ **本阶段全程自动执行**。评估→修改→评估→修改的完整循环必须连续完成，
> 中间任何一步都不得停下来等待用户反馈。仅在循环结束后展示总报告（确认点3）。

#### 执行步骤（严格按顺序，每步完成立即执行下一步）

**STEP 1**: 使用 Read 工具读取 `/tmp/pipeline-draft.md`

**STEP 2**: 执行内嵌评估（按下方「内嵌评分标准」，Claude 自行打分，不调用外部工具）

**STEP 3**: 记录评估结果到 `gate_history` 数组:
```
gate_history.append({ round: N, total: X, title: Y, passed: bool })
```

**STEP 4**: 判断是否通过（`total >= 90` 且 `title_score >= 20`）

- **通过** → 跳到 STEP 7（展示总报告，确认点3）
- **未通过且 round < max_rounds** → 立即执行 STEP 5
- **未通过且 round == max_rounds** → 跳到 STEP 7，附上警告

**STEP 5**: 根据 fix_instructions，使用 Write 工具将修改后的完整文章内容写入 `/tmp/pipeline-draft.md`

修改规则：
- 只修改 fix_instructions 涉及的部分
- 保持文章整体风格、语气、字数（±10%）
- **【绝对禁止】** 文章末尾 footer 区块（最后一条 `---` 之后的内容）原样保留，一字不改

**STEP 6**: round += 1，立即返回 STEP 1（不输出任何内容，不停顿）

**STEP 7（确认点3）**: 输出完整报告：
```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📊 质量门禁总报告
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
迭代历史:
  第1轮: XX/100, 标题 XX/20  [FAIL/PASS]
  第2轮: XX/100, 标题 XX/20  [FAIL/PASS]
  ...
最终结果: XX/100, 标题 XX/20  [✅ PASS / ⚠️ 已达最大轮数]

各维度: 标题XX/情绪XX/结构XX/案例XX/爆文XX
人味指数: X/10
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[展示文章全文]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🔴 确认点3: 请确认终稿（输入"确认"继续排版，或提出修改要求）
```

#### 内嵌评分标准（Claude 自行执行，无需调用任何工具）

评估 5 个维度，每维度 20 分，总分 100 分。**passed = total >= 90 AND title_score >= 20**。

**维度1: 标题吸引力 (20分)**

| 子项 | 分值 | 评分标准 |
|------|------|---------|
| 记忆锚点 | 7 | 含数字/人物/具体场景画面感。7=画面感极强，4=有亮点，2=平淡 |
| 好奇心触发 | 7 | 制造信息差/悬念/反常识。7=非点不可，4=有点想看，2=无感 |
| 简洁有力 | 6 | 15-25字为佳，无废字，无套路句式。6=精炼有力，3=略冗长/套路，1=拖沓 |

**维度2: 情绪共鸣 (20分)**

| 子项 | 分值 | 评分标准 |
|------|------|---------|
| 真实感 | 7 | 真实情感表达，非套路鸡汤。7=真诚动人，4=尚可，2=假大空 |
| 打动力 | 7 | 触发读者情绪（感动/共鸣/启发）。7=强烈共鸣，4=有触动，2=无感 |
| 代入感 | 6 | 读者能把自己代入场景。6=身临其境，3=部分代入，1=旁观者视角 |

**维度3: 结构完整性 (20分)**

| 子项 | 分值 | 评分标准 |
|------|------|---------|
| 逻辑通顺 | 7 | 段落间因果/递进/转折自然。7=行云流水，4=基本通顺，2=跳跃混乱 |
| 节奏合理 | 7 | 长短段交替，张弛有度。7=节奏感强，4=尚可，2=平铺直叙 |
| 首尾呼应 | 6 | 开头吸引+结尾升华，形成闭环。6=完美闭环，3=有头有尾，1=虎头蛇尾 |

**维度4: 案例深度 (20分)**

| 子项 | 分值 | 评分标准 |
|------|------|---------|
| 具体细节 | 7 | 时间/地点/人物/对话细节。7=细节丰满，4=有细节，2=笼统空泛 |
| 说服力 | 7 | 案例有力支撑观点。7=无可辩驳，4=有说服力，2=牵强 |
| 真实经历 | 6 | 来自真实经历或可信来源。6=亲身经历，3=二手可信，1=编造感强 |

**维度5: 爆文潜力 (20分)**

| 子项 | 分值 | 评分标准 |
|------|------|---------|
| 传播性 | 7 | 内容自带传播属性（争议/共鸣/实用）。7=必转，4=想转，2=不想转 |
| 分享欲 | 7 | 转发时能获得社交货币。7=转发涨身份，4=值得分享，2=无分享动力 |
| 受众匹配 | 6 | 内容与目标受众匹配度。6=精准命中，3=部分匹配，1=受众模糊 |

**附加: 人味指数 (10分，不计入总分)**

| 子项 | 分值 | 评分标准 |
|------|------|---------|
| 个人化表达 | 4 | 有"我"视角/个人经历/独特比喻。4=强烈个人风格，2=有一些，0=纯客观 |
| 语言自然度 | 3 | 像人说话而非AI输出。3=口语化自然，2=书面但不僵硬，0=明显AI腔 |
| 不可预测性 | 3 | 段落走向有意外。3=多处意外转折/自嘲，2=偶有惊喜，0=完全可预测 |

⚠️ **AI味检测要点（命中即扣分）**:
- 禁用词: 赋能/助力/维度/底层逻辑/认知升级/不可否认/毋庸置疑
- 模板句式: 首先...其次...最后、一方面...另一方面
- 元评论: 总之/综上所述/让我们一起

#### fix_instructions 生成规则

- 按「当前分数距目标分数的差距」排优先级（差距越大优先级越高）
- 标题维度同等差距时优先于其他维度
- 正文总分 >= 72 但标题 < 20 时：fix_instructions 仅针对标题，不改正文
- 每条 instruction 必须具体到可以直接执行的操作级别

### 阶段 5: 排版 (wechat-formatter)

**触发**: 用户在确认点3回复"确认"后，立即自动执行，不得停顿。

```bash
cd ~/projects/agents-bc376a3719/🧪\ 小项目与测试/wx-format
node index.js /tmp/pipeline-draft.md -t <theme> --important --cover --math --toc --images \
  -o /tmp/pipeline-article.html
```

输出最终 HTML 文件路径，提示可直接粘贴到公众号编辑器。

### 阶段 6: 微信发布 (可选)

**触发**: 排版完成后，询问用户是否发布（此处允许询问，因为发布是破坏性操作）

```bash
node index.js /tmp/pipeline-article.html --publish wechat --draft-only \
  --publish-title "$PIPELINE_TITLE" --publish-author "$PIPELINE_AUTHOR"
```

注意: 需要设置 WECHAT_APP_ID 和 WECHAT_APP_SECRET 环境变量。
草稿模式下仅创建草稿，不会自动发布。发布成功后返回 media_id。

## --from-draft 模式完整流程

```
1. 读取草稿文件（Read 工具）
2. 写入 /tmp/pipeline-draft.md（Write 工具）
3. 输出："✅ 草稿已加载，进入质量门禁循环..."
4. 执行阶段4（质量门禁，完全自动，max_rounds=3）
5. 展示确认点3总报告，等待用户确认
6. 用户确认后，立即执行阶段5（排版）
7. 询问是否发布（阶段6）
```

**--from-draft 模式只有1个确认点（确认点3），阶段1/2/3全部跳过。**

## 自动衔接逻辑（完整流程）

| 节点 | 行为 |
|------|------|
| 用户确认选题（确认点1） | 立即自动进入阶段2（大纲） |
| 用户确认大纲（确认点2） | 立即自动进入阶段3（全文扩写） |
| 阶段3全文完成 | 立即自动进入阶段4（门禁循环） |
| 门禁每轮未通过 | 立即自动修改，立即自动开始下一轮评估 |
| 门禁循环结束 | 展示总报告（确认点3），等待用户确认 |
| 用户确认（确认点3） | 立即自动进入阶段5（排版） |
| 阶段5排版完成 | 询问是否发布（阶段6，允许询问） |

## Examples

### Example 1: 完整流程

**输入**: `/wechat-pipeline "AI套娃思维" --type opinion`

**执行流程**:
1. 选题: 获取 AI 相关热点 → 用户确认方向
2. 大纲: 生成大纲+5标题 → 用户确认
3. 全文: 扩写 → 立即自动进入门禁循环
4. 门禁: 第1轮评估→(不通过)→立即修改→第2轮评估→...→总报告 → 用户确认
5. 排版: 生成 HTML → 询问是否发布

### Example 2: 从草稿开始（最常用场景）

**输入**: `/wechat-pipeline --from-draft ~/articles/draft.md`

**执行流程**:
1. 读取草稿，写入 /tmp/pipeline-draft.md
2. **立即**开始第1轮门禁评估（不停顿，不询问）
3. 第1轮: 82/100 → 未通过 → **立即**修改 → **立即**第2轮
4. 第2轮: 91/100 → 通过 → 展示总报告（确认点3）
5. 用户确认 → **立即**排版 → HTML 输出

### Example 3: 从选题开始

**输入**: `/wechat-pipeline --from-topic --type story`

**执行流程**:
1. 获取全平台热点 → 用户选择方向
2. 后续同完整流程

## 错误处理

| 场景 | 处理 |
|------|------|
| 选题获取失败 | 跳过热点，让用户直接输入方向 |
| 写作 AI 失败 | 重试一次，仍失败则保存当前进度 |
| 门禁3轮未达标 | 输出当前最佳版本 + 警告 + 剩余问题清单 |
| 排版失败 | 输出 Markdown 版本作为备选 |
| 发布失败 | 检查 API 凭证和 IP 白名单，跳过发布保留 HTML |
